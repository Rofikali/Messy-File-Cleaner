### STATX-MOUNT-EVAL-01 — scope and hypothesis

Existing LINUX-PATH-EVAL-01 tested openat2 confinement and descriptor identity, not statx mount metadata. Hypothesis: descriptor-relative statx with an explicit STATX_MNT_ID request and checked returned mask can distinguish a mount identifier from inode identity, while agreeing with conventional fstat device/inode metadata. First test uses only a private mkdtemp fixture with one regular file, its hard link and a separate regular file. It compares directory and file mount IDs, device/inode/type against fstat, and demonstrates that sharing a mount does not establish same file identity. No privileged mount, namespace change, actual cross-mount comparison or bind-mount discrimination has been tested. Future bounded research may compare already provisioned mounts without modifying them. An ordinary mount ID is namespace-local, can be reused, and is not a persistent identity or authorization token. See [statx(2)](https://man7.org/linux/man-pages/man2/statx.2.html). Missing headers/required mask or policy-denied initial syscall -> NOT VERIFIED (77); subsequent inconsistent results fail. No version-based assumption or silent fallback. No production path or mover change.

Implementation: private Linux BUILD_TESTING target, compile-check installed libc statx and fields; explicit STATX_TYPE/STATX_INO/STATX_MNT_ID request, AT_EMPTY_PATH on open descriptors; compare device major/minor, inode and type. No file content changes beyond creating disposable empty files; exact cleanup. No new dependencies, upstream source copy, spending or production integration. Local NOT RUN, candidate CI pending. HLD/LLD production unchanged. Rollback: revert candidate. For adoption require actual cross-mount evidence, error/unsupported behavior, performance/cost measurement and separate review; no FS-01B authorization.
