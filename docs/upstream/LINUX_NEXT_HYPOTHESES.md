## Third bounded experiment — inherited descriptor authority

**Linux-native next research (2026-11-28):** #301 merged at `b9588dd697e2579a9391fd40105e5a96773ebe0d`; 14/14 exact-head checks PASS, GCC C17 Release and hosted Ubuntu C17 84/84, both Landlock tests PASS (not skipped); integrated-main 10/14 checks PASS, 4 pending at inspection; independent review unverified. LANDLOCK-PREVIEW-EVAL-01 third candidate tests inherited writable descriptor positive control and explicit close-before-restriction negative control in disposable child processes. No claim of full descriptor inventory, same-UID isolation, production sandbox, imported kernel code or FS-01B/release closure. Candidate CI pending.

Hypothesis: a descriptor opened for writing before the child applies Landlock WRITE_FILE restrictions remains writable even when a new write-open is denied. O_CLOEXEC does not close a descriptor at fork. The positive control changes only a dedicated disposable one-byte file from X to Y using pwrite; parent verifies exact byte and inode/size/link count. A fresh child explicitly closes its inherited copy before applying the same policy; new write-open must fail EACCES and pwrite through that closed descriptor must fail EBADF. Parent verifies the Y byte is unchanged. Parent retains cleanup authority; unexpected success, incorrect error, byte or identity changes fail the test. Unsupported Landlock returns skip 77 only; both baseline tests remain separately registered. This is a narrow descriptor lifecycle reference, not a universal descriptor sanitization routine, not a proof about all inherited resources, and not protection from another process. No production integration, network, dependency or spend. Local NOT RUN; CI pending. Reference: [Landlock userspace API](https://docs.kernel.org/userspace-api/landlock.html) and [open(2)](https://man7.org/linux/man-pages/man2/open.2.html). Rollback: revert candidate.
